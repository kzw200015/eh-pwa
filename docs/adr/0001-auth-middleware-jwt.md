# 鉴权用两个中间件加无状态 JWT，不用 Passport

本站账号的鉴权只有三件事：用户名和密码换一张无状态令牌、请求头带令牌认人、少数接口放行。Passport 为多种登录策略设计，只用一种 JWT 策略时它多出来的是一层策略注册与间接调用，读代码时要先弄懂它的约定。所以鉴权就是 `auth/session.ts` 的两个 Hono 中间件：要登录的路由挂 `signedIn`，没登录回 401；公开接口上要认出登录者的挂 `maybeSignedIn`，没登录时 `userId` 是 `null`。中间件逐条写在路由上、排在入参校验之前，没登录的请求先拿到 401。

令牌是 HS256 的 JWT，用 Hono 自带的 `hono/utils/jwt` 签发与校验，签名密钥是由主密钥经 HKDF 派生的子密钥，只认 HS256，不照令牌头里自称的算法去验。密码算 argon2id（`Bun.password`），参数显式写死；账号不存在时也算一遍假哈希，响应快慢不泄露哪些用户名存在。

## Consequences

- 「默认要登录」不由框架保证：公开接口的清单由接口测试按整张路由表锁住，漏挂 `signedIn` 的代价是那条测试失败，而不是把接口裸露出去。新增公开接口要同时改那份清单。
- 不在一组路由上 `use` 中间件：`use` 按路径前缀挂，eh 下要登录的路由与公开的图片接口共用前缀。
- 令牌无状态，服务端不存已签发的令牌，没法提前作废，也没有 logout 接口；要全端下线得另加令牌版本号并在每次校验时查库。
- 图片接口由 `<img>` 直接发起、带不了请求头，不走令牌，靠地址签名认人，每条接口自己校验签名。
- 登录不限制同时在算的哈希个数：每算一次要占 64 MiB，大量并发的乱填登录会把内存顶上去。注册默认关闭、账号都是自己人，这个风险先接受。
