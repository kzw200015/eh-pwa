# 后端用 Hono，前端经 hono/client 从后端推断接口类型

前后端之间只有接口这一处：前端要是按字符串拼路径、靠类型参数声明响应，后端改了路径或字段，前端编译照样通过，只能在运行时发现。所以后端用 Hono：路由是一串链式调用，入参 schema 与处理函数的返回值都留在类型里，整个应用导出一个 `App` 类型；前端用 `hono/client` 按这个类型生成客户端，路径、路径参数、查询串、请求体与响应一律由推断得到，写错当场编译失败。

`hono/client` 推断出的请求是 schema 的**输入**（带默认值的字段可选，路径参数是 transform 之前的字符串），处理函数经 `c.req.valid()` 拿到的是**输出**，两头分开。所以请求 schema 可以照常用 zod 的 `.default()` 与 `.transform()`，如搜索条件的默认值、阅读历史的游标在校验时就解开。按输出类型推断请求的框架（如 Elysia 的 Eden）做不到这一点：带默认值的字段前端也得给全，转换只能挪进处理函数。

几处取舍：

- **前端 `import type { App }` 直接引后端源码**，不另建声明文件或 project references。前端的 tsconfig 给后端的 `@server/*` 别名配一份同样的解析，`hono` 是前端的依赖，版本与后端一致。
- **入参校验经 `validate.ts` 包一层 `@hono/zod-validator`**：不合格时直接抛 400，由 `app.ts` 的 `onError` 回成统一的 `{code, message}`。按 `zValidator` 默认的做法回一个响应的话，zod 的错误对象会被推断成每条接口的一种响应，混进前端的类型。
- **不用依赖注入，模块就是单例**：配置、连接池、出网、子密钥在模块被导入时建好，服务写成导出函数的模块，缓存是模块级的状态，路由是模块级的 Hono 实例，调用处用命名空间导入（`galleryService.search(…)`）。测试只需要换掉出网，所以只给出网留一个替换口（`replaceOutbound`）；真要单独替换某个服务来测，就把那个模块改成工厂函数加默认实例。
- **监听由 `server.ts` 自己 `Bun.serve`**：Hono 的应用只是一个 fetch 函数。`idleTimeout` 设成 30 秒：Bun 默认 10 秒，手动同步标签译名这类要十几秒的请求会被掐断。静态文件用 `hono/bun` 的 `serveStatic`，只挂在 GET 上（它自己不看方法）。
- **数据访问用 Drizzle**：表结构写在各领域的 `*-tables.ts`，drizzle-kit 生成迁移，服务启动时先执行迁移再监听。

## Consequences

- 路由要从 `new Hono()` 一路链式写下来，子路由经 `.route(前缀, 子路由)` 挂上，`App` 类型里才有全部接口。
- 接口收什么、回什么都定义在后端：请求 schema 挂在路由上、就近定义，响应类型定义在产出它的模块里、由服务标注返回类型。前端的出入参类型一律从 `api.ts` 的调用推导，共享包只放两端都要执行的规则（见 ADR-0002）。
- 只回成败的写接口回 204：`c.body(null)` 回 200 的话，`parseResponse` 会把它推断成 `string`、读出一个空串，204 才推断得出 `undefined`。
- 前端的调用写法按路由的原样展开：`api.eh.galleries[":gid"][":token"].$get({ param: { gid: String(gid), token } })`，请求体放在 `json`、查询串放在 `query`，`signal`、`keepalive` 放在第二个参数的 `init` 里。
- 前端只有 `httpClient.ts` 引后端，且只能 `import type` `App`，按值引用会把后端代码连同 drizzle 打进前端。由 lint 挡住：前端别处引 `@server/**` 一律报错，`httpClient.ts` 只允许 `import type`，并开着 `typescript/no-import-type-side-effects`——前端开着 `verbatimModuleSyntax`，`import { type X }` 编译后会留下一句副作用导入。
- 前端的类型检查按前端的配置读到后端源码：后端能被 `App` 追到的代码要在两边的配置下都通过，不写构造器参数属性（两边都开着 `erasableSyntaxOnly`），不用 ES2023 之后才有的内置方法（前端的 `lib` 到 ES2023）。前端的类型检查也看得到 Bun 的全局类型，因为后端源码引了 `bun`。
- 配置在模块被导入时读定，一个测试文件只能有一套配置。
